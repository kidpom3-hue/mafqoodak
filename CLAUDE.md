# CLAUDE.md — مفقودك (Mafqoodak)

Lost-and-found PWA. First deployment: Technical College Al-Ahsa (office id `tc-ahsa`, ref code `TCA`). The owner is a beginner developer who reads Arabic; keep explanations in Arabic and changes small and well-commented.

## Stack
- Plain HTML/CSS/ES modules, **no build step**. Firebase JS SDK loaded from gstatic CDN, version pinned to `12.19.0` in `js/firebase.js`, `js/ai.js` and the `modulepreload` links in `index.html` (change all together).
- `index.html` lists every app module in `<link rel="modulepreload">` (parallel download = faster first render): **add any new `js/` module there and to `SHELL` in `sw.js`** (bump its `CACHE` version). A tiny inline script in `<head>` applies the saved theme (`mfq:theme`) and language (`mfq:lang`) before first paint.
- Firebase Auth (Google + Email/Password), Cloud Firestore, optional Firebase AI Logic (Gemini) behind `SETTINGS.enableAI`.
- App Check (phase H0): `firebase-app-check.js` (same pinned version, static import + modulepreload) is initialised in `firebase.js` right after `initializeApp` (before Auth/Firestore/AI) with `ReCaptchaV3Provider(SETTINGS.appCheck.siteKey)` and `isTokenAutoRefreshEnabled: true`, only when `siteKey` is set (`''` = off, app unchanged); `debug: true` sets `self.FIREBASE_APPCHECK_DEBUG_TOKEN` for localhost. Enforcement is switched on manually in the Firebase console after monitoring (README). The service worker only caches same-origin files, so gstatic modules are never in `SHELL`. Test stubs for it live in `tools/a11y.mjs`.
- Hosted on GitHub Pages (relative paths only — the app lives under `/mafqoodak/`). `firebase.json` also allows Firebase Hosting.
- Must stay on the free Spark plan: no Cloud Storage (photos are compressed JPEG data URLs in Firestore docs, < 350 KB), no Cloud Functions, no phone SMS auth.

## Layout
- `js/config.js` — Firebase config + app settings (the only file a new deployer edits).
- `js/firebase.js` — init + `dbx` helper (string paths: `dbx.set('items/abc', data)`, `dbx.watch(col, [[field, op, value]], cb)`).
- `js/state.js` — global state `S`, auth listener, Firestore subscriptions, role helpers (`isStaffHere`, `modes`), photo/name caches, `write()` wrapper with Arabic error toasts.
- `js/ui.js` — router (`ROUTES`, `go`, `back`), header/nav/sheet rendering, `hydrate()` (lazy photos `img[data-photo]` and names `[data-uname]`).
- `js/views/*.js` — pure functions returning HTML strings (`home.js` = landing page for the chosen office + «وجدت غرضاً» guide; visitor default route is `home`; `privacy.js` = privacy policy & terms, route `privacy`). Item share links use `#item/<officeId>/<itemId>` (parsed in `state.js`). **Always escape user data with `esc()`.**
- `js/workflow.js` — **every item/claim status transition** (`approveClaim(c, {reason})`, `reactivateClaim`, `rejectClaim`, `askQuestion`, `verifyHandover(c, {name, last4})`, `releaseReservation`, `setItemStatus`, `itemSaved`, `dropFound`, `disposeItems`, `deleteItem`) plus staff access changes (`grantStaff`, `revokeStaff`, `setAdmin`, each logging `perm:*` per office). `commit(b, guarded)`: for rule-guarded transitions (approve, code handover, reactivate) a `permission-denied` becomes `FlowError(t('wf.race'))` («سبقك موظف آخر…»). `approveClaim` on an item `reserved` without a real approved claim first commits a separate batch making it `available`. `itemSaved(item, {created, fromReport, fromFound})` runs after an item form save: one batch with the log (`create`/`edit`/`receive`) plus the report's `staffPick` or the found notice's `received`. `commit(b)` appends the batch's log entries to `S.logs` (the open timeline) without a re-read. Each one is a single `writeBatch` + a `logs` entry; guard failures throw `FlowError` with an Arabic `msg` that `write()` toasts. Never change item/claim status anywhere else. Exception: creating a new item stays sequential (items first, then itemSecrets/photos) because those rules use `get()`, which does not see writes in the same batch.
- `js/views/gov.js` (phase F, government-platform style, **no government or Vision 2030 logos**): route `service` (`{id: claim|report|handin}`; without id = index) = service card with description, beneficiaries, requirements, numbered steps, timing (`offices.reviewDays` default 2, `pickupDays`), fees «مجاناً», channels (office place/hours/phone), «ابدأ الخدمة»; route `numbers` «مؤشرات المكتب» for visitors (one read of `publicStats/{officeId}`, `loadPublicStats`); route `a11y` «بيان إمكانية الوصول». Linked from the home link rows, the office page and the footer (services, accessibility, privacy & terms).
- Staff access (invites): the old visitor «اطلب صلاحية موظف» card, the `join` route/`vJoin` and `submitForm('join')` are gone. Admin «الصلاحيات» tab = «دعوة موظف» form (`data-form="invite"`, `wf.inviteStaff`) + pending invites (`S.invites`, admin subscription) with «إلغاء» (`wf.cancelInvite`) + current staff/admins. An invite applies only to accounts without a `staff` doc (self-create only); other staff changes stay admin-only.
- «طلباتي» and staff lists (PR 3, display only): `vMine` = «يحتاج انتباهك» box (`claimNeed`/`reportNeed`: code ready, unanswered question, rating due, suggested item, stale report; each row «افتح» → `openCard(tab, key, ended)` in `actions.js`) + tabs `role="tablist"` (claims / reports / found, only when the user has more than one type; last tab in LS `mineTab`; arrow keys RTL-aware, Home/End) + per list: active items (by latest event) then `<details class="ended">` «منتهية (n)». Every card is `mcard()` from `common.js` (`<details data-card="c:|r:|f:|s:|sf:|sr:<id>">`, summary = title/number/status + «الخطوة التالية»; opens automatically when it needs attention; user toggles kept in `CARD_OPEN`/`ENDED_OPEN` across live re-renders via a capturing `toggle` listener). The pickup code sits at the top of its card (big digits, copy, deadline). Staff «الاستلام»: «بانتظار قرارك» (oldest first, waiting time) → «بانتظار الحضور» (nearest deadline first, warning under a day) → «تسليمات قادمة» (pending hand-in notices, moved here from the reports tab, with the code search) → «منتهية» (claim history on demand). Staff «البلاغات»: with a staff pick → open → «مغلقة» (`loadClosedReports()` on demand, `S.closedReps`).
- H4 display rules: «طلباتي» always shows its 3 tabs (`.tl` full / `.ts` short label below 420px; grey `.tab-n` = active count, hidden at 0; red `.count` = unseen `alertKeys()` of that tab via `unseenKeys()`/`keyTab()`, cleared by `markSeenKeys(keys)` on tab click or card open, persisted in LS `seen`); ended items are a plain `h3.ended-h` «منتهية (n)» + muted cards (no `<details>`); a new unopened card has class `new` (`mcard({fresh, muted})`, no chevron). «يحتاج انتباهك» rows have «لاحقاً» (`attLater`, LS `snoozed`, key from `attKey()` changes on each new event). Staff «الاستلام»/«البلاغات» use sub-tabs `subTabs(g, defs)` (`S.staffSub[g]`, action `staffSub`; default = first non-empty) «قراري | الحضور | قادمة | منتهية» and «لها مرشّح | مفتوحة | مغلقة»; unread from `staffKeys()` (`sc`/`sa`/`sf`/`sr` keys); the bottom-nav «الاستلام» badge = unread «قراري» only; `#s-stats` only in «المستودع». Header «Aa» (`displaySheet`) holds theme + text size; below 480px Aa/EN/login are icon-only. Footer = full-bleed `--hero-bg` band (`footer(o)` in `home.js`). The three-number `.stats-band` lives in browse (`#br-stats`, whole-office numbers, not filtered). `refresh()` restores focus by element id after a re-render.
- `js/views/audit.js` — route `audit` (admins): «سجل العمليات», logs of a chosen office loaded on demand with `officeId ==` + `action in` (`AUDIT` filters in `state.js`: direct handover, delete, dispose, `perm:*`).
- `views/common.js` `catFields(catId, src, mode)` renders colour/brand + `d_<k>` inputs inside `<div id="cat-fields" data-mode="item|report|claim">` (labels `df.<k>`, placeholder `df.<k>.ph`, per-category override `df.<cat>.<k>`, pick options `df.<k>.<opt>`, colour label `df.<cat>.color`); `onCatChange` re-renders it keeping typed values in `form.catMemo`. A 4th arg `part` ('req' | 'opt') splits the claim form (H0): required fields stay visible in `#cat-fields`, optional ones go into `#cat-fields-opt` inside `<details id="cl-more">` «تفاصيل إضافية تزيد فرصة قبول طلبك» together with the place, date and — unless it is required for the category (`!claimHasRequired`) — the free proof; it opens in edit mode, from a report, or when it holds values; `formErr(form, msg, field)` opens the `<details>` around the failing field and focuses it. `readDetails()` in `actions.js` builds `details` from non-empty values only. The staff comparison (`claimChecks`/`claimCompare`) adds a row per question: num/last4/pick exact, approx within max(20%, 20), text ✓ only on containment/shared word (never an automatic ✗); summary «تطابق n من total» over rows that have a result; the weak-approval warning uses the ratio. Principle: what visitors can see is not evidence — the (secret) place counts; the date never gets ✓ and is not in `total` (✗ only when impossible: lost after it was found or more than 14 days before); the colour counts only when the public photo is `'none'`/`false` («ظاهر في الصورة» for `'clear'`/`'blur'`, since blurring keeps the colour; the item form hints this under the photo mode).
- `js/migrate.js` — one-time move of legacy item fields into `itemSecrets` when the staff dashboard opens.
- `js/actions.js` — `ACT` click handlers (`data-act="name"`) and `submitForm` (forms use `data-form="kind"`).
- `js/constants.js` — categories (`CATS`, with `en` and `subsEn` parallel to `subs`; optional `claim: {fields, req, details, hint}` — `fields` ⊂ ['color','brand'], `req` = required ones in the claim form, `details` = category questions `[{k, type: num|approx|last4|text|pick, req: both|staff|claim, opts, as}]` (`as` = compare with an existing claim field such as `claimantName`/`idLast4` instead of asking twice), `hint` = proof hint key `cl.h.<id>`; `DETAIL_KEYS` must equal `detailKeys()` in the rules; helpers `claimOf`, `claimHasRequired` (then the free proof is optional «تفاصيل أخرى تثبت أنه لك»), `detailValue` (Arabic-Indic digits → Latin, numbers only, text ≤ 80, pick ids only); `staffCheck` = staff tip key `sc.<id>`, `retentionDays` used when shorter than the office's, suggested `disposal`, `publicName`/`publicEn` for the public title; helpers `claimOf(cat)`, `keepDaysOf(cat, office)`; `cash` is sensitive, public title «مبلغ مالي»), colors (`en`, `altEn`), office types, statuses (`en`), SVG icon paths, and display helpers: `catName`, `subLabel`, `colorName`, `statusLabel`, `otypeName`, office `oName`/`oShort`/`oPlace`/`oHours`/`oCity`/`spotLabel` (English office fields `nameEn`, `shortEn`, `cityEn`, `placeEn`, `hoursEn`, `spotsEn[]` same order as `spots`; fall back to Arabic). Stored values (`sub`, `spot`, category id) stay Arabic; translate only on display. `searchWords()` adds English names to search text. `icon('back'|'fwd')` gets class `dir` and is mirrored in LTR by CSS.
- `js/utils.js` — `refCode(n)` (ref charset, used by `makeRef` and the 6-char hand-in code), `normCode`, `disposalLabel`; dates (locale-aware, Latin digits in both languages), text normalisation/search, `matchScore` heuristic, SHA-256, image compression, `toast`, `showTitle(i)` (display title), `spotText`/`spotName` (translated place via a hook set in `state.js`).
- `js/i18n.js` + `js/i18n/ar.js`, `js/i18n/en.js` — **all user-visible text** (buttons, toasts, errors, aria-label/alt/placeholder, FAQ, privacy page, `document.title`). `t('key', {vars})`, counts `tp('n.item', n)` (Intl.PluralRules per language; Arabic `n.item` nominative, `n.itemAcc` accusative, `n.itemGen` genitive…; never `${n} غرضاً`). `LANG`, `isEn()`, `setLang()` (sets `<html lang dir>`, LS `mfq:lang`). Default: saved choice, else browser language (`ar*` → Arabic, else English). `users.lang` stores the signed-in user's choice. `auth.languageCode = LANG`. Values written to the database stay Arabic: use `tAr('sys.…')` for system notes and show them with `noteText()`. Dictionary strings are trusted HTML; user data passed as vars must go through `esc()`. **Never put Arabic text in `js/*.js` or `js/views/*.js`** (except `constants.js`, `sample-data.js`, `config.js`): `node tools/check-i18n.mjs` fails on it and on dictionary key mismatches — run it before every PR.

## Data model (Firestore)
`publicStats/{officeId}` (public read, written by that office's staff; aggregate numbers only) · `config/app` {ownerUid} · `admins/{uid}` {role, addedAt, addedBy} (owner can't be removed; admins list subscribed for admins as `S.adminList`) · `staff/{uid}` {offices[], approvedAt, approvedBy} · `staffInvites/{email lowercased}` {offices, createdBy, createdAt} (admin writes; the invitee reads only with the same verified token email; accepted automatically by `tryInvite()` in `state.js` → `wf.acceptInvite`: one batch creating `staff/{uid}` with exactly the invite's offices + deleting the invite + a `perm:grant` log per office written by the new staff member, all rule-guarded; unverified email/password accounts see «وثّق بريدك لتفعيل صلاحية الموظف» in the verify bar, and «وثّقته» calls `checkInvite()`) · `staffRequests/{uid}` (legacy, replaced by invites: create/update admin only, kept readable/deletable for cleanup, no longer subscribed) · `users/{uid}` {name,email,photo,lastSeen,lang ('ar'|'en')} + `users/{uid}/private/codes` {codes: {claimId: code}} · `offices/{id}` · `reports/{id}` (+ `rejected[]`, `editedAt`) · `reportPhotos/{reportId}`.

Items are split so the public listing never reveals what proves ownership:
- `items/{id}` — **public**: officeId, ref, cat, sub, title, foundDate, photo, status, createdBy, createdAt, updatedAt, sample (+ optional fromReport, fromFound, reservedFor, returnedAt, disposal, disposedAt). **No `spot`** (phase E5): the found place is the answer to «أين فقدته؟», so visitors never see it (cards, `miniItem` outside `staffView()`, item page, public search `textScore(q, i, false)`, AI prompt). `title` is generic (`publicTitle(cat, sub)` = sub or category name). `photo` is `'clear'` | `'blur'` | `'none'` (hidden publicly, original kept for staff) | `false`. Rules reject any of color/brand/desc/bldg/room/storage/details/spot here (`secretKeys()`), on create **and** on any update — so a legacy item that still has a public `spot` can't change status until it is moved: `migrateSpots()` in `migrate.js` (on the staff dashboard, every loaded item incl. `loadExtraItems`) commits one batch per item (`itemSecrets` set-merge `{officeId, spot}` + `items` update `{spot: deleteField()}`), and every item update in `workflow.js` goes through `itemUpdate(b, i, patch, secret)`, which adds the same move to its batch. Legacy value `true` = old clear public photo, converted by `js/migrate.js`.
- `itemSecrets/{id}` — **staff only**: {officeId, title (detailed), color, brand, desc, spot (found place), bldg, room, storage, finderNote (who handed it in without the app: name — last 4), details (category answers, string values, keys from `DETAIL_KEYS`, never in `items`)}. Colour/brand are saved empty when the category has none. Staff views use `full(item)` from `state.js` (public + secret, so `spot` comes from `itemSecrets`; `S.secrets` is subscribed only for staff).
- `itemPhotosPrivate/{id}` — **staff only**: {officeId, data} = clear original (photo key `p_<id>`).
- `itemPhotos/{id}` — public {data}: the same image for `'clear'`, a real 24px downscale from `makeBlur()` for `'blur'`, no doc for `'none'`/`false`.
- `claims/{itemId}_{uid}` — fixed id = one claim per user per item; {editedAt (owner edit, phase G), itemId, officeId, uid, proof, color, brand, lostSpot, bldg, room, lostDate, reportId?, claimantName (as on the card), idLast4 (4 digits), details (same keys as `itemSecrets.details`), no (short request number `REQ-XXXX` from `refCode(4)`; old claims show `claimNo(c)` = `REQ-` + last 4 of the id, searchable in the staff claims tab), rating (int 1–5, once, only by the owner of a `done` claim) + ratingNote (≤ 300) + ratedAt (account deletion clears `ratingNote`, keeps `rating`), status, handoverNote («استلمه: الاسم — آخر 4: 1234», set by `verifyHandover` after «طابقتُ البطاقة»), codeHash = sha256(claimId + ':' + code), createdAt, pickupBy (ms, set on approve = now + office.pickupDays), note}. Status: `pending` → `approved` → `done`, or `rejected` / `expired` (pickup missed or item made available again) / `cancelled` (item handed over directly, archived, disposed or deleted). Staff see a comparison against `itemSecrets`. A reserved item still accepts competing claims. Staff can never decide their own claim (UI + rules). Claims and reports need a verified email (`request.auth.token.email_verified`). Rules guard the chain of custody: `approveOk` (item `available` before, `reservedFor == claimId` after, same batch), `doneOk`, items become `reserved` only for an approved claim and `returned` only with a `done` claim or a non-empty `itemSecrets.handoverNote` in the same batch. Conflict of interest (`conflictOf(c, i)` in `state.js`: claimant = `foundReports.uid` of `item.fromFound`, fetched once via `ensureFinder`, or `item.createdBy`) shows a red warning and approving needs a reason (claim `note` + log). `expired`/`cancelled` claims can be reactivated from staff claim history (`approved` + item reserved if available, else `pending`, log `reactivate`); the claimant's item page explains and shows office hours/phone instead of a claim button.
- Item status: `available`, `reserved` (only via approve, `reservedFor` = claim id), `returned`, `archived`, `disposed` (+ public `disposal`: donated|destroyed|authority|finder|other — `finder` only when `SETTINGS.allowReturnToFinder` and the item has `fromFound`; the finder then sees «أصبح الغرض لك» in «طلباتي», `disposedAt`; private `itemSecrets.disposalNote`). Direct handover stores `itemSecrets.handoverNote`. `offices/{id}.pickupDays` (default 7), `retentionDays` (default 90).
- `logs/{id}` — append-only chain of custody {officeId, itemId, claimId, reportId, action, by, at, note}, written by `workflow.js`. Access changes: `perm:grant|revoke|admin|unadmin`, empty `itemId`, target uid in `note`.
- `reports` also have `details` (optional answers, copied into a claim), `closedReason` ('self' «وجدته بنفسي» with a confirmation | 'office' set automatically by `autoClose()` in `state.js` when a linked claim — `reportId` or the staff pick — is `done`), and `pickRejected` (the owner's «ليس غرضي» = the current `staffPick`; staff see it and the item leaves that report's candidates). The pick box offers «هذا غرضي — اطلب استلامه» (route `claim` with `{id, report}` prefills from the report and sets `reportId`). While a linked claim is pending/approved the report shows it instead of the close button. Stats show closed reports by reason (office / self / none).
- `reports`: open reports older than 60 days from `renewedAt || createdAt` (`isStale`) ask their owner «هل ما زلت تبحث؟» (نعم → `renewedAt`, وجدته → closed), are hidden in the staff tab by default («أظهر القديمة (N)», `S.showStale`) and excluded from matching.
- `foundReports/{id}` — finder's hand-in notice {officeId, uid, cat, sub, spot, bldg, room, foundDate, note, code (6 chars, shown to the finder as a small «رقم الإشعار» line; the staff code search appears only above `CODE_SEARCH_MIN` = 5 pending notices), status: `pending`|`received`|`cancelled`, createdAt (+ receivedAt/receivedBy/itemId by staff, cancelledAt by finder)}. Created from route `handin` («وجدت غرضاً»), finder sees them in «طلباتي» (`S.myFound`, by uid); staff subscribe to their office's `pending` ones (`S.found`) in the reports tab. «استلمته» opens the item form (`fromFound`) → item gets `fromFound`, notice becomes `received` (in `wf.itemSaved`). The finder sees "back with its owner" when the linked item is `returned`. Account deletion deletes non-received notices and anonymises received ones (`uid: 'deleted'`, `note: ''`).
- Verification question: staff `wf.askQuestion(c, q)` sets `claims.question/askedAt/askedBy` (+ log `ask`); the claimant answers from «طلباتي» (`answer/answeredAt`, only while `pending`). `answered(c)` = answer newer than the question; a new question replaces the old one.
- Item edit rewrites the whole doc: keep fields the form doesn't show (`fromReport`, `fromFound`, `reservedFor`, `returnedAt`, `disposal`, `disposedAt`, and secret `handoverNote`/`disposalNote`) — see the loop in `actions.js`. `finderNote` is a form field.
- Terminology (one name per concept in both dictionaries): «بلاغ فقدان» Lost report · «طلب استلام» Claim · «إشعار تسليم» Hand-in notice · «رقم القيد» Reference · «رقم الطلب» Request no. · «رمز الاستلام» Pickup code; defined in the collapsed «المصطلحات» `<details>` on the services index (route `service` without id, `TERMS` in `gov.js`). ## Conventions
- UI is Arabic (RTL) or English (LTR). Use logical CSS properties only (`inset-inline-start`, `padding-inline`, `text-align:start`), never physical left/right for layout. Colors only via CSS tokens in `:root` (light) and the two dark-mode blocks.
- Back button: `go()` and `openSheet()` call `history.pushState({mf: 1[, sheet: 1]})`; a `popstate` listener in `ui.js` closes an open sheet or steps back through `S.hist`. `back()` and `closeSheet()` go through `history.back()` so browser history and `S.hist` stay in sync. Never call `pushState` from inside the `popstate` listener. Scroll (G6): `history.scrollRestoration = 'manual'` (main.js); `go()` saves `S.route.y = scrollY` on the page it pushes to `S.hist`, and `backStep()` restores it after `renderAll()` via `restoreScroll(y)` (now + next frame, once more if the page was still short), so the iOS swipe-back shows no jump to the top. Bottom-nav/tab navigation still starts at the top. Lazy images must keep a reserved height (`aspect-ratio`; `.detail-photo` is 16/7 only when it has no `img` at all).
- Images: only `data:image/...` values (item/report photos) and `https://*.googleusercontent.com/` avatars may be put into `img.src` (see `safeData`/`safeAvatar` in `ui.js`). Item photos load lazily via `IntersectionObserver` in `hydrate()`.
- Routes with `live: true` re-render on data changes; forms are `live: false` so typing is never lost. Views with inputs that must keep focus use an `update()` partial renderer (see `updateBrowse`, `updateStaff`).
- Write order matters for rules: create the parent doc (item/report) before its photo doc; delete the photo before the parent.
- Sensitive category (`ids`) never stores photos.
- Visitors never see match percentages: `maybeFor(r)` (same category, same type if given, found −1…+30 days from loss). Percentages (`candidatesFor(r, n, full)`) are for staff only.
- Renamed type names keep old stored values working via `LEGACY_SUBS` / `subName()` in `constants.js` (display, search, matching).
- Test locally with `python -m http.server 8000` → `http://localhost:8000`.
- CSS: print-label styles are scoped to `.labels>.label` (plain `.label` is the form-label class).
- Mobile header (H0): below 560px the sign-in button is icon-only (`.login-btn`, text kept for `aria-label`), the office chip drops its type icon and the English wordmark hides, so `oShort` shows in full from 320px. Staff dashboard below 480px: stats in a 3-column grid; below 768px «أضف غرضاً» is a full-width `.add-full` and the tools row moves into «المزيد» (`staffMore` sheet).
- Touch targets ≥ 36px (the office `.switch` is 24px tall but its `::before` extends the hit area to 40px). Inline links in sentences get padding with negative margin (`.legal-link .link`).
- Charts/figures follow the dataviz rules: one axis, thin bars (≤ 24px, 4px rounded data end), text never in series colours, a table view for every chart. New chart colours must be validated in both modes before use.
